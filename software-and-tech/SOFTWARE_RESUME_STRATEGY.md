# 📄 SOFTWARE_RESUME_STRATEGY.md — Representing Tool Proficiency Honestly

> **How to put software on your resume without exaggerating.**
> Complements [`resume-positioning.md`](resume-positioning.md) with role-specific examples.

---

## The Core Rule

> **Only list a tool if you can defend it in an interview.**
> **Never claim a level you cannot demonstrate.**

---

## Proficiency → Resume Mapping

| Level | Resume Representation | Example |
|:-----:|:----------------------|:--------|
| **L1 — Familiar** | Do NOT list (or "familiar with" only) | "Familiar with BIM concepts" |
| **L2 — Working** | List with a specific example | "Modeled a G+3 frame in ETABS" |
| **L3 — Project-capable** | List with project evidence | "Designed a G+10 building in ETABS per IS 456" |
| **L4 — Advanced** | List only if deeply defensible | "Developed OpenFOAM solver modifications" |

## Bad vs Good Examples

### Structural Engineer

```
❌ Bad:  "Expert in ETABS"
❌ Bad:  "Proficient in STAAD.Pro"
✅ Good: "Structural modelling and analysis of a G+10 RCC building using ETABS,
          including response spectrum analysis per IS 1893"
✅ Good: "Performed steel frame analysis and design in STAAD.Pro per IS 800"
```

### Water Resources Engineer

```
❌ Bad:  "Know HEC-RAS"
✅ Good: "Built a 1D/2D HEC-RAS flood model for a 50 km river reach,
          calibrated against observed water levels (<5% error)"
```

### Python for Engineering

```
❌ Bad:  "Proficient in Python"
✅ Good: "Developed Python automation to process 200+ HEC-RAS output files,
          reducing post-processing time from 3 hours to 15 minutes"
```

### Data Analyst

```
❌ Bad:  "Advanced SQL"
✅ Good: "Wrote complex SQL queries (window functions, CTEs) to analyze
          500K+ transaction records for churn analysis"
```

## The Bullet Formula

```
[Action verb] + [what you did] + [tool] + [result/impact]
```

| Component | Example |
|:----------|:--------|
| **Action verb** | Developed, Built, Modeled, Automated, Analyzed |
| **What you did** | flood model, building design, data pipeline |
| **Tool** | HEC-RAS, ETABS, Python |
| **Result/impact** | reduced time, <5% error, cost saving |

---

## Quantification Rules

```
✅ Use numbers you can defend:
    "reduced processing time from ~3 hours to ~20 minutes"
    "calibrated to <5% error against gauge data"

❌ Never fabricate:
    "reduced cost by 90%" (unless measured)
    "expert in X" (unless you can answer deep questions)
```

## Skills Section Format

### Recommended (with labels)

```
Technical Skills:
    - Python (NumPy, Pandas, Matplotlib) — Working (L3)
    - HEC-RAS (1D/2D flood modeling) — Working (L3)
    - AutoCAD (2D drafting, detailing) — Working (L3)
    - Excel (BOQ, data analysis) — Working (L3)
    - Git/GitHub — Basic (L2)
```

### Alternative (no labels)

```
Technical Skills:
    - Python: automated hydraulic calculations, data analysis
    - HEC-RAS: 1D/2D flood modeling, calibration
    - AutoCAD: structural drawings, detailing
    - Excel: BOQ preparation, rate analysis
```

## Interview Defense Checklist

For every tool on your resume, prepare:

```
1. What is it? (Basic)
2. What have you done with it? (Practical)
3. How does your workflow work? (Technical)
4. What if results look wrong? (Troubleshooting)
5. How do you know it's correct? (Validation)
6. Why this tool vs alternatives? (Comparison)
7. Explain your project. (Project Defense)
```

See [`software-interview-questions.md`](software-interview-questions.md) for the full bank.

## What NOT to Do

| ❌ Don't | ✅ Do |
|:---------|:------|
| List 15 tools | List 4–6 you can defend |
| Claim "Expert" after one tutorial | Say "Working proficiency" with a project |
| Say "Advanced Python" after one script | Say "Working proficiency" with evidence |
| List a tool you can't discuss | Leave it off — better to underclaim |
| Use vague "proficient in" | Use specific, quantified achievements |
