# 📄 Resume Positioning for Software & Technology

> **Teach the difference between "Know Python" and "Developed a Python workflow to automate hydraulic data processing and generate validation plots."**
> **Do NOT permit inflated claims.**

---

## The Core Principle

> **Only list a tool on your resume if you can answer basic practical questions about it.**
> **Never claim proficiency you cannot defend in an interview.**

---

## Proficiency Labels

Use these honest labels:

| Label | Meaning | When to Use |
|:------|:--------|:------------|
| **Awareness** | Know what it does, where it's used | Don't list on resume (or list as "familiar with") |
| **Basic** | Can perform standard workflows | List with specific examples |
| **Working** | Can independently complete a project | List with project evidence |
| **Advanced** | Can handle complex modelling/automation | List with strong evidence |

### Resume Rule

```
Awareness → Do NOT list (or list only in "familiar with" section)
Basic     → List only with a specific example
Working   → List with project evidence (recommended)
Advanced  → List only if you can defend it deeply
```

---

## The Bullet Formula

```
[Action verb] + [what you did] + [tool] + [result/impact]
```

### Examples

```
❌ Bad:  "Proficient in Python"
❌ Bad:  "Know Python programming"
❌ Bad:  "Used HEC-RAS for coursework"

✅ Good: "Developed Python workflow to automate Manning's equation calculations
         for 200+ channel cross-sections, reducing design iteration time from
         4 hours to 20 minutes"

✅ Good: "Built HEC-RAS 2D flood model for a 50 km river reach, calibrating
         against observed water levels with <5% error, and generated flood
         inundation maps in GIS"

✅ Good: "Created Power BI dashboard tracking 100+ construction projects,
         enabling real-time visibility into schedule delays and cost overruns"
```

## Technical-to-Business Translation

| Technical Claim | Business Translation |
|:----------------|:---------------------|
| "Used Pandas to clean data" | "Processed 50,000+ data points, reducing analysis time by 70%" |
| "Wrote Python scripts" | "Automated repetitive calculations, saving 3 hours per week" |
| "Built a CFD model" | "Simulated flow to optimize design, reducing material cost by 15%" |
| "Made a dashboard" | "Enabled stakeholders to make data-driven decisions in real time" |
| "Used SQL" | "Queried databases to extract insights for business decisions" |

---

## Quantification Guide

### What to Quantify

```
- Time saved (hours/days)
- Data volume processed (rows, files, GB)
- Accuracy/error (%, R², convergence)
- Cost reduction (₹, %)
- Scale (number of projects, sections, models)
- Performance improvement (%, speedup)
```

### How to Quantify Honestly

```
Rule: Only use numbers you can defend.

If you don't have a real number, use a conservative estimate:
    "reduced processing time from ~3 hours to ~20 minutes"
    (not "reduced by 90%" unless you measured it)

Never fabricate metrics. Interviewers will probe.
```

---

## What NOT to Do

| ❌ Don't | ✅ Do Instead |
|:---------|:-------------|
| List 15 tools | List 4–6 you can defend |
| Claim "Advanced Python" after one script | Say "Working proficiency" with a project |
| Say "Expert in OpenFOAM" without solver experience | Say "Working proficiency" with validation |
| List a tool you can't discuss | Leave it off — better to underclaim |
| Use vague "proficient in" | Use specific, quantified achievements |
| Inflate project scope | Describe exactly what you did |

## Skills Section Format

### Recommended

```
Technical Skills:
    - Python (NumPy, Pandas, Matplotlib) — Working
    - SQL (joins, window functions) — Working
    - HEC-RAS (1D/2D flood modeling) — Working
    - GIS (QGIS, GeoPandas) — Basic
    - Git/GitHub — Working
    - LaTeX — Working
```

### Alternative (if you prefer no labels)

```
Technical Skills:
    - Python: automated hydraulic calculations, data analysis
    - SQL: querying, aggregation, window functions
    - HEC-RAS: 1D/2D flood modeling, calibration
    - GIS: watershed delineation, flood mapping
    - Git/GitHub: version control, portfolio hosting
```

## Interview Defense

For every tool on your resume, prepare:

```
1. What is it? (Basic)
2. What have you done with it? (Practical)
3. How does your workflow work? (Technical)
4. What if results look wrong? (Troubleshooting)
5. How do you know it's correct? (Validation)
6. Why this tool vs alternatives? (Comparison)
7. Explain your project. (Project Defense)
```

See [`software-interview-questions.md`](software-interview-questions.md) for the full question bank.

## Resume Checklist

```
☐ Every tool listed can be defended in an interview
☐ Every bullet uses the Action + What + Tool + Result formula
☐ Numbers are honest and defensible
☐ Proficiency labels are honest (Awareness/Basic/Working/Advanced)
☐ No inflated claims
☐ GitHub portfolio linked and organized
☐ 4-6 tools max, not 15
☐ Technical skills translated to business impact
```
