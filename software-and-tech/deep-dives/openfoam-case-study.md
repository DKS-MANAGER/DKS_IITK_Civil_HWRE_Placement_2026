# 🌊 OpenFOAM Deep-Dive Case Study

> **Tool:** OpenFOAM (open-source CFD toolbox)
> **Level:** L2 → L3 (from first case to a complete steady incompressible flow simulation)
> **Prerequisite:** [`cfd-tech.md`](../cfd/cfd-tech.md), Linux basics ([`linux-dev-tools.md`](../developer-tools/linux-dev-tools.md)), fluid mechanics fundamentals

This is a **hands-on case study**, not a feature list. You will build a complete OpenFOAM case end-to-end: **steady incompressible flow around a cylinder** (a classic benchmark). Each step explains **what** to do, **why** it matters, and **how to check** you did it correctly.

---

## 🎯 What You Will Build

A **2D steady-state incompressible flow** around a circular cylinder using:
1. `blockMesh` for the structured mesh
2. `simpleFoam` (SIMPLE algorithm) for the steady solver
3. `paraFoam` / ParaView for visualization
4. A **mesh independence study** to verify convergence

By the end you will understand the full OpenFOAM workflow and can discuss it in an interview.

## 📁 STEP 1 — Set Up the Case Directory

OpenFOAM uses a **case directory** structure. Create it:

```bash
mkdir -p $FOAM_RUN/cylinderCase
cd $FOAM_RUN/cylinderCase
```

The case structure:

```
cylinderCase/
├── 0/                    # Initial and boundary conditions
│   ├── U                 # Velocity field
│   └── p                 # Pressure field
├── constant/
│   ├── transportProperties   # Fluid properties (viscosity)
│   └── polyMesh/             # Mesh (generated by blockMesh)
├── system/
│   ├── blockMeshDict     # Mesh definition
│   ├── controlDict       # Solver settings, time control
│   ├── fvSchemes         # Discretization schemes
│   └── fvSolution        # Linear solvers and algorithms
```

**Why:** OpenFOAM is file-based. Every setting is a text file. Understanding the structure is the key to using OpenFOAM.

**Check:** The directory structure exists.

## 📐 STEP 2 — Define the Mesh (blockMeshDict)

Create `system/blockMeshDict`. This defines a 2D domain around a cylinder.

```cpp
/*--------------------------------*- C++ -*----------------------------------*/
FoamFile
{
    version     2.0;
    format      ascii;
    class       dictionary;
    object      blockMeshDict;
}
// * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * //

convertToMeters 0.1;

vertices
(
    // Outer boundary (square domain)
    (-20 -20 0)   // 0
    ( 20 -20 0)   // 1
    ( 20  20 0)   // 2
    (-20  20 0)   // 3
    // Inner boundary (cylinder, radius 0.5)
    ( 0.5  0 0)   // 4
    ( 0  0.5 0)   // 5
    (-0.5  0 0)   // 6
    ( 0 -0.5 0)   // 7
);

blocks
(
    hex (0 1 2 3 4 5 6 7) (100 100 1) simpleGrading (1 1 1)
);

edges
(
    arc 4 5 (0.3536 0.3536 0)
    arc 5 6 (-0.3536 0.3536 0)
    arc 6 7 (-0.3536 -0.3536 0)
    arc 7 4 (0.3536 -0.3536 0)
);

boundary
(
    inlet
    {
        type patch;
        faces
        (
            (0 1 4 7)   // left face
        );
    }
    outlet
    {
        type patch;
        faces
        (
            (2 3 6 5)   // right face
        );
    }
    top
    {
        type patch;
        faces
        (
            (1 2 5 4)   // top face
        );
    }
    bottom
    {
        type patch;
        faces
        (
            (3 0 7 6)   // bottom face
        );
    }
    cylinder
    {
        type wall;
        faces
        (
            (4 5 6 7)   // cylinder surface
        );
    }
);

mergePatchPairs ();

// ************************************************************************* //
```

**Why:** `blockMesh` creates a structured mesh. The `arc` edges create the circular cylinder. The `boundary` section defines the patches (inlet, outlet, top, bottom, cylinder).

**Check:** Run `blockMesh` and verify no errors.

---

## 🧱 STEP 3 — Generate the Mesh

```bash
blockMesh
```

**Check:** The mesh is created. Run `checkMesh` to verify quality:

```bash
checkMesh
```

Look for:
- **Mesh OK** (no errors)
- **Non-orthogonality** < 70 (lower is better)
- **Skewness** < 4 (lower is better)

**Why:** `checkMesh` validates mesh quality. Poor mesh → inaccurate or diverging results.

## 🧱 STEP 4 — Set Fluid Properties

Create `constant/transportProperties`:

```cpp
FoamFile
{
    version     2.0;
    format      ascii;
    class       dictionary;
    object      transportProperties;
}

transportModel  Newtonian;

nu              [0 2 -1 0 0 0 0] 0.01;   // kinematic viscosity
```

**Why:** `nu` (kinematic viscosity) controls the Reynolds number. With U = 1 m/s and cylinder diameter D = 0.1 m (convertToMeters 0.1), Re = U·D/ν = 1·0.1/0.01 = 10 (laminar).

---

## 🧱 STEP 5 — Set Initial and Boundary Conditions

Create `0/U` (velocity):

```cpp
FoamFile
{
    version     2.0;
    format      ascii;
    class       volVectorField;
    object      U;
}

dimensions      [0 1 -1 0 0 0 0];

internalField   uniform (1 0 0);   // initial velocity: 1 m/s in x

boundaryField
{
    inlet
    {
        type            fixedValue;
        value           uniform (1 0 0);
    }
    outlet
    {
        type            zeroGradient;
    }
    top
    {
        type            slip;
    }
    bottom
    {
        type            slip;
    }
    cylinder
    {
        type            fixedValue;
        value           uniform (0 0 0);   // no-slip on cylinder
    }
}
```

Create `0/p` (pressure):

```cpp
FoamFile
{
    version     2.0;
    format      ascii;
    class       volScalarField;
    object      p;
}

dimensions      [0 2 -2 0 0 0 0];

internalField   uniform 0;

boundaryField
{
    inlet
    {
        type            zeroGradient;
    }
    outlet
    {
        type            fixedValue;
        value           uniform 0;
    }
    top
    {
        type            zeroGradient;
    }
    bottom
    {
        type            zeroGradient;
    }
    cylinder
    {
        type            zeroGradient;
    }
}
```

**Why:** Boundary conditions define how the flow enters, exits, and interacts with the cylinder. Inlet is fixed velocity, outlet is fixed pressure, cylinder is no-slip.

## 🧱 STEP 6 — Configure the Solver (controlDict)

Create `system/controlDict`:

```cpp
FoamFile
{
    version     2.0;
    format      ascii;
    class       dictionary;
    object      controlDict;
}

application     simpleFoam;

startFrom       startTime;
startTime       0;

stopAt          endTime;
endTime         1000;

deltaT          1;

writeControl    runTime;
writeInterval   100;

purgeWrite      0;

writeFormat     ascii;
writePrecision  6;
writeCompression off;

timeFormat      general;
timePrecision   6;

runTimeModifiable true;
```

**Why:** `simpleFoam` is the steady incompressible solver. `endTime` 1000 with `deltaT` 1 means 1000 iterations (steady solver iterates in pseudo-time).

---

## 🧱 STEP 7 — Configure Discretization (fvSchemes)

Create `system/fvSchemes`:

```cpp
FoamFile
{
    version     2.0;
    format      ascii;
    class       dictionary;
    object      fvSchemes;
}

ddtSchemes
{
    default         steadyState;
}

gradSchemes
{
    default         Gauss linear;
    grad(p)         Gauss linear;
}

divSchemes
{
    default         none;
    div(phi,U)      Gauss linearUpwind grad(U);
    div(phi,k)      Gauss upwind;
    div(phi,epsilon) Gauss upwind;
    div((nuEff*dev2(T(grad(U))))) Gauss linear;
}

laplacianSchemes
{
    default         Gauss linear corrected;
}

interpolationSchemes
{
    default         linear;
}

snGradSchemes
{
    default         corrected;
}

wallDist
{
    method          meshWave;
}
```

**Why:** `fvSchemes` defines how the governing equations are discretized. `linearUpwind` for convection is more accurate than pure upwind.

---

## 🧱 STEP 8 — Configure Linear Solvers (fvSolution)

Create `system/fvSolution`:

```cpp
FoamFile
{
    version     2.0;
    format      ascii;
    class       dictionary;
    object      fvSolution;
}

solvers
{
    p
    {
        solver          PCG;
        preconditioner  DIC;
        tolerance       1e-06;
        relTol          0.01;
    }
    U
    {
        solver          PBiCG;
        preconditioner  DILU;
        tolerance       1e-06;
        relTol          0.01;
    }
}

SIMPLE
{
    nNonOrthogonalCorrectors 0;
    consistent      yes;
    residualControl
    {
        p               1e-4;
        U               1e-4;
    }
}

relaxationFactors
{
    fields
    {
        p               0.3;
    }
    equations
    {
        U               0.7;
    }
}
```

**Why:** `fvSolution` defines the linear solvers and the SIMPLE algorithm settings. Under-relaxation factors (0.3 for p, 0.7 for U) stabilize the iteration.

## 🧮 STEP 9 — Run the Solver

```bash
simpleFoam
```

Monitor the output:
- **Residuals** should decrease over iterations
- Look for "SIMPLE solution converged" or check residuals reach the target

**Check:** The residuals for p and U decrease. The solution converges.

## 📊 STEP 10 — View Results in ParaView

```bash
paraFoam
```

Or use ParaView directly:
```bash
paraview cylinderCase.foam
```

Visualize:
1. **U** (velocity) — contours and streamlines
2. **p** (pressure) — contours
3. Check the flow field around the cylinder

**Why:** Visualization confirms the physics. For Re=10, you should see a steady, symmetric flow with a recirculation zone behind the cylinder.

**Check:** The flow is symmetric (steady laminar). There's a recirculation bubble behind the cylinder.

## 🔍 STEP 11 — Mesh Independence Study

1. Create **3 meshes** with different resolutions (e.g., 50×50, 100×100, 200×200 cells)
2. Run each and extract the **drag coefficient** (Cd)
3. Plot Cd vs. mesh size
4. Confirm the results converge (Cd stops changing)

**Why:** A mesh independence study proves your results are not mesh-dependent. This is essential for credible CFD.

**Check:** Cd converges to a stable value as the mesh refines. Compare with the published value for Re=10 (Cd ≈ 2.8).

## 🔍 STEP 12 — Troubleshoot Common Errors

| Error | Cause | Fix |
|:------|:------|:----|
| "FOAM FATAL ERROR" | Syntax error in a dictionary | Check the file for typos, missing semicolons |
| "Divergence" (residuals blow up) | Unstable scheme, bad mesh, wrong BC | Reduce under-relaxation, improve mesh, check BCs |
| "Non-orthogonality too high" | Bad mesh | Refine mesh, use `corrected` snGrad |
| "Negative pressure" | Wrong pressure reference | Set a fixedValue at outlet |

**Why:** These are common issues in real CFD. Knowing how to fix them is a strong interview signal.

## 🧠 Interview Questions You Can Now Answer

1. **"Walk me through an OpenFOAM case you ran."**
   → "I ran steady incompressible flow around a cylinder. I built the mesh with blockMesh, set up the boundary conditions in the 0/ directory, configured simpleFoam, ran a mesh independence study, and validated the drag coefficient against published data."

2. **"What is the SIMPLE algorithm?"**
   → "SIMPLE (Semi-Implicit Method for Pressure-Linked Equations) is an iterative algorithm for steady incompressible flow. It solves the momentum equation, then corrects pressure to satisfy continuity."

3. **"What is a mesh independence study?"**
   → "It's running the same case on progressively finer meshes and checking that the results converge. If the solution changes with mesh, it's not converged."

4. **"What's the difference between steady and transient solvers?"**
   → "Steady solvers (simpleFoam) assume the flow doesn't change with time. Transient solvers (pimpleFoam) capture time-varying flow, needed for unsteady or turbulent flows."

5. **"How do you validate a CFD model?"**
   → "I compare the computed results (e.g., drag coefficient, velocity profiles) against experimental data or published benchmark values, and quantify the error."
