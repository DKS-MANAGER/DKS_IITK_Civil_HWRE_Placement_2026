# PROJECT DEFENCE

> **The canonical project defence system.** Prepare every important project so you can defend it under deep technical questioning. Use this for projects, internships, research, and thesis.

---

## The Project Defence Template

For each important project, prepare all of the following:

| Component | What to Prepare |
|:----------|:----------------|
| **30-second explanation** | One breath, high-level, compelling |
| **2-minute explanation** | Structured, with key details |
| **Problem** | What problem did you solve? Why does it matter? |
| **Methodology** | Step-by-step approach |
| **Assumptions** | What did you assume? Why? |
| **Tools** | What tools/software did you use? |
| **Calculations** | Key numbers, formulas, results |
| **Validation** | How did you verify your results? |
| **Results** | What did you achieve? Quantified |
| **Limitations** | What are the weaknesses? |
| **Practical application** | How is this used in the real world? |
| **Future improvements** | What would you do differently? |
| **Likely technical questions** | Anticipate the hard questions |
| **Likely cross-questions** | Questions from other subjects |

---

## The 30-Second Explanation

**Formula:** Problem → Approach → Result

> "I modeled flood inundation for the [river] basin using HEC-RAS. I calibrated the model to historical flood events, achieving a ±10% match, and produced inundation maps for a 100-year return period that informed flood-risk zoning."

**Keep it:** 1 breath · 3 sentences · compelling · no jargon overload

---

## The 2-Minute Explanation

**Structure:**

1. **Problem (20 sec):** Context + why it matters
2. **Methodology (40 sec):** Approach + tools + key steps
3. **Results (30 sec):** Quantified outcomes
4. **Limitations + Future (30 sec):** Honest assessment + what's next

---

## Deep-Dive Preparation

### Problem
- What was the real-world problem?
- Why was it important?
- Who was the stakeholder?

### Methodology
- What was your step-by-step approach?
- Why did you choose this method over alternatives?
- What were the key decisions?

### Assumptions
- What did you assume?
- How would results change if assumptions changed?
- Were assumptions reasonable?

### Tools
- What software/tools did you use? → [Software Hub](../software-and-tech/README.md)
- Why those tools?
- What were the limitations of the tools?

### Calculations
- What were the key formulas? → [Formula Sheet](../aptitude/FORMULA_SHEET.md)
- What were the key numbers?
- Can you reproduce the calculation on the spot?

### Validation
- How did you verify results?
- Against what benchmark/field data?
- What was the error/uncertainty?

### Results
- What did you achieve?
- Quantified impact
- What was the final deliverable?

### Limitations
- What were the weaknesses?
- What would you improve?
- Be honest — interviewers respect honesty

### Practical Application
- How is this used in industry?
- Who would use your results?
- What decisions does it inform?

### Future Improvements
- What would you do differently?
- What additional data would help?
- What new methods could improve it?

---

## Likely Technical Questions

For each project, prepare answers to:

1. "Walk me through your methodology"
2. "Why did you use [tool/method]?"
3. "What were your key assumptions?"
4. "How did you validate your results?"
5. "What were the limitations?"
6. "What would you do differently?"
7. "What was the hardest part?"
8. "How does this apply in practice?"

---

## Likely Cross-Questions

Interviewers often cross into other subjects:

- **Hydraulics project →** "How does this relate to open channel flow?"
- **Structural project →** "What load combinations did you consider?"
- **Geotech project →** "What soil parameters did you use?"
- **Data project →** "How did you handle missing data?"

> Prepare 2–3 cross-questions per project from adjacent subjects.
